# 05 - 数据库与安全

## 1. 表清单

`sql/init.sql` 一次性建全量表（`CREATE TABLE IF NOT EXISTS` 幂等）+ 初始数据。

### 1.1 按租户属性分类

**租户内表**（继承 `TenantBaseModel` 或手动声明 `TenantID`，查询必须 `TenantScope`）：

| 表 | 说明 |
|----|------|
| `sys_user` / `sys_role` / `sys_post` / `sys_dept` | 用户/角色/岗位/部门 |
| `sys_agreement` / `sys_file` | 协议/文件（**注意：dept、agreement 由全局表迁为租户表**，见迁移 `2026-09-25-dept-tenant.sql`、`2026-09-25-agreement-tenant.sql`） |
| `sys_operation_log` / `sys_login_log` | 日志（手动声明 TenantID） |
| `pay_order` / `pay_member` / `pay_member_level` / `pay_member_tag` / `pay_points_log` | 支付与会员 |

**全局表**（继承 `BaseModel`，**无 tenant_id 列，套 TenantScope 会 SQL 报错**）：

`sys_menu`、`sys_config`、`sys_dict_type`、`sys_dict_data`、`sys_tenant`。

**纯关联表**（无 tenant_id 列，租户隔离在 Service 层校验）：

`sys_user_role`、`sys_user_post`、`sys_role_menu`、`pay_member_tag_rel`。
关联表的 user_id 与 role_id 可能分属不同租户 —— 写入前必须先按租户查出被引用方并比对数量。

**系统表**：`casbin_rule`（自研适配器的策略表，但授权关系实际由 `sys_role_menu` 自动生成同步，无需手工维护）。

### 1.2 基础字段

```go
type BaseModel struct {      // 全局表
    ID, CreateBy, UpdateBy, CreatedAt, UpdatedAt, DeletedAt, Remark
}
type TenantBaseModel struct { // 租户表，额外 TenantID
    BaseModel
    TenantID uint `gorm:"index;comment:租户ID"`
}
```

软删除统一 `DeletedAt gorm.DeletedAt`（JSON 序列化为 `-`，不外泄）。

## 2. 软删除与唯一索引

唯一索引**不区分软删除记录**。`Delete` 必须在事务内：

1. `common.FreedUniqueValue(value, id, maxLen)` 改写唯一字段（`_del_<id>`）释放占用；
2. 清理关联表避免孤儿记录。

| 表 | 唯一列 | 列长 | 需清理关联表 |
|----|--------|------|--------------|
| `sys_user` | `username` | 64 | `sys_user_role`、`sys_user_post` |
| `sys_role` | `code` | 64 | `sys_user_role`、`sys_role_menu` |
| `sys_post` | `(tenant_id, code)` | 64 | `sys_user_post` |
| `sys_config` | `config_key` | 191 | — |
| `sys_dict_type` | `type` | 128 | — |
| `pay_member` | `phone` / `member_no` | 20 / 32 | `pay_member_tag_rel` |

> ⚠️ **不要用 `BeforeDelete` 钩子做释放**：`db.Delete(&Model{}, id)` 不加载模型，钩子里读到空字段会把值覆盖成 `_del_<id>`（数据损坏）。必须显式先查后改。

## 3. 认证（JWT）

- Secret：环境变量 `JWT_SECRET` 优先；**生产默认值拒绝启动**（`config.ValidateSecurity`，≥32 字符）；
- Access 2 小时 / Refresh 7 天，**issuer 不同**，`ParseToken` 只接受 access、`ParseRefreshToken` 只接受 refresh；
- 双通道传输：`security.token_transport` = `header` / `cookie` / `both`，Cookie 用 HttpOnly + SameSite=Lax（HTTPS 加 Secure）；
- Refresh Token **必须登记用户维度索引** `RefreshTokenSetKey(userID)` —— refresh 本身是随机串，没有索引就无法按用户批量吊销，改密/禁用/登出会静默失效；
- **吊销链路**（全部 fail-closed，Redis 异常拒绝请求）：
  - 登出 → access 加黑名单 `RevokeToken` + refresh 从集合移除；
  - 改密/禁用 → `revokeUserTokens`：`SMembers` → 逐个删 `RefreshTokenKey` → 删集合 + 置 `UserTokenRevokedKey`；
- `AuthService.Logout` 的 userID 来自 JWT claims，**不要把 access token 当 refresh token 传**（历史 bug：拼出 `refresh_token:<accessToken>` 删了不存在的键）。

## 4. 登录限频与验证码

- **限频**：IP 与账号双维度各 5 次失败锁 15 分钟（仅失败计数，成功清零）；计数用 `SETNX` 带 TTL 建键 —— 「先 INCR 再 EXPIRE」若 INCR 成功而 EXPIRE 失败，key 永不过期会把 IP/账号**永久锁死**；
- **验证码**（点选式，强制）：`GET /captcha/generate` → `POST /captcha/verify`（写一次性凭证 `captcha:verified:<token>`，5 分钟）→ `POST /auth/login` 带 `captchaToken`（`binding:"required"`）→ `ConsumeVerifiedToken` 校验并消费，不可复用；
- 登录失败统一返回「用户名或密码错误」，防用户名枚举；
- ⚠️ 禁止对同一请求体做两次 `ShouldBindJSON`（读完即耗尽，第二次必失败；若错误被 `_ =` 丢弃，校验分支成死代码 —— 历史 bug）。

## 5. 授权（Casbin RBAC）

- 模型 `config/casbin/model.conf`，自研 GORM 适配器；
- 策略来源：`sys_role_menu` + `sys_menu.permission` → 启动时与角色/菜单变更后 `SyncPoliciesFromRoleMenus` 自动同步，**无需手工维护 `casbin_rule`**；
- 主体 = 角色 code；`admin` 持 `*/*/*/*` 通配；
- 路由权限码经 `protected()` 登记，**未登记默认 403**；
- 授权收敛：非 admin 不能授予自己没有的权限（`assertGrantable` / `OperatorHoldsPermissions`），`admin` 角色码保留不可改删；
- 角色缓存 `rbac:roles:<tenant>:<user>`，`ClearRoleCache` 在角色变更后失效。

## 6. 密码与配置安全

- bcrypt（`DefaultCost`）；强度校验：大小写/数字至少两种、禁空格（Create / ResetPassword / ChangePassword）；
- `sys_config` 敏感项（key 命中 secret/password/key/pem/private/token）接口返回打码 `******`；内部取值用 `FindByPrefixRaw`；`BatchSave` 跳过 `******` 防覆盖；
- 生产默认的 `jwt.secret` / `database.password` 拒绝启动；
- 操作日志请求体自动脱敏（见 [03-中间件与公共层.md](./03-中间件与公共层.md) §2 operation_log）。

## 7. 上传安全

- 扩展名白名单（`upload.allow_exts` 配置注入）+ 危险扩展名硬编码黑名单始终生效；
- 大小上限 `upload.max_size`（MB），`max_body_size` 必须更大（配置校验强制）；
- `/uploads` 匿名可读 → `UploadSecurity` 补 CSP 沙箱防 SVG XSS；**密钥/证书禁止放 uploads**（写 `runtime/certs/`）；
- 删除路径穿越校验：Clean + 拒绝绝对路径/`..` + 拼接后前缀校验。

## 8. 支付安全

- **回调无鉴权**（顶层注册）但必须自验签：微信 APIv3 RSA（平台证书 10 分钟缓存）+ AES-GCM 解密；支付宝 RSA2；
- 微信请求签名串 `方法\n路径(含query)\n时间戳\n随机串\n报文主体\n` —— URL 去域名、**body 必须参与签名**（漏 body 全部 401 且回调验签连带失效）；
- **金额禁用浮点**：`int64(amt*100)` 有表示误差（19.99 → 1998），统一 `yuanToFen()` 字符串拆分；
- 回调金额比对防篡改；回调幂等 `MarkPaidIfPending`（条件更新 0→1）；
- **资金操作先抢占状态**：`ClaimRefund` 条件更新 1→4 抢占 + 影响行数判断，抢不到即拒绝 —— 防止并发双退款（详见 [02-后端业务模块.md](./02-后端业务模块.md) §2.2）；
- `genOrderNo` = 前缀 + 毫秒时间戳 + 10 位 crypto/rand hex（**不要退回时间戳+纳秒末四位**，同毫秒约 1/10000 撞号，`order_no` 有唯一索引且撞号时可能把别人的订单返回）；
- returnURL 开放重定向防护（协议 + 主机名校验）。

## 9. 多租户隔离要点

- tenantID **只从 JWT claims 取**（Tenant 中间件写入上下文），禁止 Header/Query；
- Repository 全部 `common.TenantScope(db, tenantID)`；`TenantScope(db, 0)` = 不过滤（平台级），**漏传 tenantID 会静默全表查询**；
- 关联表写入前 Service 层按租户比对数量；
- 关联查询/批量 ID 用 `UniqueNonZeroIDs` + 租户过滤。

## 10. 其他安全项

- CORS：生产必须白名单；`AllowCredentials` 配明确 Origin；开发模式放行所有来源；
- CSRF：Cookie 通道时 double-submit 校验，SameSite=Lax 主防线；
- Body 限制：`DrainBody` + `BodyLimit` 前置拦截超大请求；
- Swagger 仅非 release 模式暴露；
- 前端无 `v-html`/`innerHTML`（XSS）；富文本经 `pkg/sanitize` 净化；
- CI 安全扫描：gitleaks（密钥泄漏）+ govulncheck（依赖漏洞）+ `-race`。
