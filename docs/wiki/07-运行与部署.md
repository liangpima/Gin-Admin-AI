# 07 - 运行与部署

## 1. 环境要求

| 组件 | 要求 |
|------|------|
| Go | 1.25.x |
| Node | ≥ 22 |
| MySQL | 5.7+ / 8.0（compose 用 8.0） |
| Redis | 3.0+（compose 用 7-alpine）—— **启动强依赖，初始化失败直接退出** |

**必须从项目根目录启动**（`./server.exe`）：`log.filename`、`upload.save_path`、`casbin.model_path` 均为相对工作目录的路径，casbin 加载失败会拒绝启动。systemd 部署需显式 `WorkingDirectory`。

## 2. 首次初始化

```bash
# 1. 准备数据库（本地或 docker compose 起 mysql/redis）
mysql -u root -p < sql/init.sql        # 全量建表 + 初始数据
go run ./cmd/migrate                    # 后续增量迁移（幂等，可随时重跑）
go run ./cmd/migrate -status            # 查看迁移状态

# 2. 配置敏感项（优先环境变量，禁止生产用默认值）
export DB_PASSWORD="..." JWT_SECRET="..." REDIS_PASSWORD="..."
```

初始账号 `admin / admin123`（仅本地开发，生产必须修改）。

## 3. 本地开发

### 后端

```bash
go mod tidy
go build -o server.exe ./cmd/server
./server.exe                 # 从项目根目录启动
```

或用脚本（Windows）：

```powershell
.\run.bat                    # 杀旧进程 + 编译 + 启动后端
.\start-backend.ps1          # 仅启动后端（不杀旧进程）
```

### 前端

```bash
cd web
npm install
npm run dev                   # Vite 开发服务器
```

### 一键启动

```powershell
.\start-all.ps1               # 同时拉起 start-backend.ps1 + start-frontend.ps1
```

### 验证

- 业务端口：`config.yaml` 的 `server.port`（默认 8080）；健康检查 `GET /health`、就绪 `GET /health/ready`；
- Prometheus metrics 独立端口（与业务端口分离）；
- Swagger：**仅非 release 模式**暴露（`make swagger` 重新生成）；
- 前端登录页走完整验证码流程：generate → verify → login。

## 4. 常用命令

```bash
# 后端
go build -o server.exe ./cmd/server   # 编译
go test ./...                          # 测试（含 conventions 架构约定测试）
go vet ./...                           # 静态检查
swag init -g cmd/server/main.go -o docs  # 生成 Swagger

# Makefile
make build / run / clean
make test / coverage                   # 覆盖率门槛 ~74%
make lint                              # golangci-lint / gofmt / vet
make check                             # 总门禁：backend + frontend + deploy + migrations + secrets
make check-race                        # -race 竞态
make check-vuln                        # govulncheck
make check-secrets                     # gitleaks
make migrate / migrate-status
make swagger / swagger-baseline        # 生成 / 固化 API 基线
make deps                              # go mod tidy

# 前端（web/ 下）
npm run dev / build / typecheck / lint / test / format:check
```

## 5. Docker 部署

### 镜像（`Dockerfile`）

多阶段构建：

1. `golang:1.25-alpine` builder：`go mod download` → `CGO_ENABLED=0` 编译 `go-admin` 与 `migrate` 两个二进制；
2. `alpine:3.20` 运行时：ca-certificates + tzdata，复制 `config/casbin/`、`sql/`，预建 `logs / uploads / runtime/certs` 目录，`EXPOSE 8080`，`ENTRYPOINT ["/app/go-admin"]`。

### 编排（`docker-compose.yml`）

| 服务 | 镜像 | 说明 |
|------|------|------|
| mysql | `mysql:8.0` | utf8mb4、+08:00 时区；`sql/init.sql` 挂 `docker-entrypoint-initdb.d` 首次自动初始化；端口默认不暴露宿主机 |
| redis | `redis:7-alpine` | 数据卷持久化 |
| app | `gin-admin:latest` | 挂载 `deploy/config.docker.yaml`（只读）、`uploads` / `runtime`（证书）/ `logs` 卷；`depends_on` mysql+redis |
| web | `gin-admin-web:latest` | nginx 静态托管 + 反代，`${WEB_PORT:-8080}:80` |

启动：

```bash
docker compose up -d --build
```

流量路径：浏览器 → web(nginx, 8080) → app(8080 内网) → mysql/redis。密钥经环境变量注入（compose 读取宿主环境）。

## 6. CI 流水线（`.github/workflows/ci.yml`）

触发：push / pull_request（同 ref 的并发组自动取消旧运行）。

| Job | 检查项（均为阻断） |
|-----|--------------------|
| **后端（vet / test / build）** | `go vet` → `go test`（含 `router/swagger_routes_test.go` 校验路由与文档一致）→ `scripts/check-coverage.sh`（覆盖率门槛）→ 编译 server/migrate → **swagger 一致性**（钉死 `swag@v1.16.4`，`make swagger` 后与入库 docs/ 比对，不一致即失败）→ **破坏性变更检测**（`scripts/check_breaking_changes.py` 对比 `docs/swagger-baseline.json`，改接口需 `make swagger-baseline` 固化新基线）→ `scripts/check-migrations.sh` → **govulncheck@v1.1.4** 依赖漏洞扫描 → **gitleaks@v8.30.1** `git .` 密钥泄漏扫描（不用 `dir .`，误报过多） |
| **race** | `go test -race ./...` 数据竞争检测 |
| **frontend** | `npm ci` → typecheck → lint（0 警告）→ vitest → prettier 格式 → `npm run build`（含 bundle 体积门禁）→ `npm audit --audit-level=high` |
| **lint** | golangci-lint（action 钉死 commit） |

## 7. 生产上线检查清单

- [ ] `mode: release`，`jwt.secret` ≥ 32 字符、`database.password` 非默认（否则**拒绝启动**）；
- [ ] `cors.allow_origins` 明确白名单；
- [ ] `token_transport` 按需求设定，Cookie 通道时 `cookie_secure: true`（HTTPS）；
- [ ] 修改初始 admin 密码；确认所有业务角色已通过菜单勾选权限（`sys_role_menu`）；
- [ ] `sql/migrations` 已全部执行（`migrate -status`）；
- [ ] `log.filename` 目录可写（启动时自动探测，失败拒绝启动）；
- [ ] 支付证书在 `runtime/certs/`（**不在 uploads/**）；OSS 等密钥在 `sys_config`（接口打码）；
- [ ] 日志保留 `log.db_retention_days`（默认 90 天，每天 03:00 清理）已确认；
- [ ] 反向代理设置 `WorkingDirectory`（非容器部署时）或工作目录为项目根；
- [ ] `make check` 本地全绿后再发版。
