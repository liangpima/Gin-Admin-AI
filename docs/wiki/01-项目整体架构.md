# 01 - 项目整体架构

## 1. 项目概述

Gin-Admin 是一套基于 Go + Gin + GORM + Vue3 + Element Plus 的多租户后台管理框架，包含系统管理（用户/角色/菜单/部门/岗位/配置/字典/日志/文件/协议）、支付（微信/支付宝）、会员（会员/等级/标签/积分）四大业务域。

### 技术栈

| 层 | 技术 |
|----|------|
| 后端 | Go 1.25.14、Gin v1.10、GORM v1.25、MySQL 5.7+、Redis 3.0+ |
| 认证授权 | JWT（golang-jwt/v5）+ Casbin RBAC（自研 GORM 适配器） |
| 前端 | Vue 3.5、Element Plus 2.9、Vite 6、TypeScript 5.7、Pinia 2.3 |
| 支撑 | Zap 日志（lumberjack 轮转）、Viper 配置、Swagger、robfig/cron、prometheus |
| 存储上传 | 本地 / 阿里云 OSS / 腾讯云 COS / MinIO（`pkg/upload` 自动选择） |

Go 模块名为 `go-admin`（见 [go.mod](file:///i:/phpstudy_pro/WWW/go/go.mod)）。

## 3. 三层架构（13 条铁律摘要）

规范全文见 [AGENTS.md](file:///i:/phpstudy_pro/WWW/go/AGENTS.md)，核心约束：

```
Controller (接口层)      参数接收、binding 校验、common.Success/FailWith 返回
  └── Service (业务层)   业务判断、事务控制 db.Transaction、只调本模块 Repository
        └── Repository   纯 GORM 数据访问，方法必须带 tenantID 参数
```

关键红线：

1. **禁止跨模块访问 Repository**——跨模块数据通过调用对方 Service；
2. **所有查询必须走 Repository**——禁止裸 `db.Where()`；
3. **多租户自动附加 tenant_id**——统一 `common.TenantScope(db, tenantID)`，`tenantID=0` 表示不过滤（平台级）；
4. **所有接口统一 Response**——Service 错误唯一出口是 `common.FailWith(c, err)`；
5. **受保护路由必须 `protected()` 登记权限码**——未登记默认 403。

> `internal/conventions` 包含对上述约定的机械化测试（例如断言每个 Repository 方法签名含 tenantID），CI 中运行。

## 4. 服务启动链

入口 [cmd/server/main.go](file:///i:/phpstudy_pro/WWW/go/cmd/server/main.go)，按序执行：

1. `config.Init()` — Viper 加载 `config/config.yaml`，支持环境变量覆盖（`DB_PASSWORD` / `JWT_SECRET` / `REDIS_PASSWORD`）；
2. `config.ValidateSecurity()` — 生产环境（mode=release）若 JWT secret / DB 密码仍为默认值**拒绝启动**；
3. `logger.Init()` — Zap 初始化，日志父目录自动创建并做可写性探测，失败拒绝启动；同时输出 stdout + 文件（lumberjack 轮转）；
4. `config.DevelopmentWarnings()` — 开发环境弱配置告警；
5. `database.Init()` — MySQL 连接，失败即退出；
6. `cache.Init()` — **Redis 强依赖**（refresh token / 黑名单 / 限频 / 验证码 / 角色缓存），失败即退出；
7. `middleware.InitCasbin()` — 加载 `config/casbin/model.conf` + GORM 适配器；
8. 注入 `SetRoleResolver`（角色解析，来自 `rbac_resolver`）与 `SetOperationLogWriter`；
9. `upload.SetAllowedExts()` + `upload.Init()` — 从 `sys_config` 读取 OSS/COS/MinIO 配置；
10. `router.Setup(mode)` — 注册全部路由（详见 §6）；
11. 注册定时任务（日志清理，每天 03:00，10 分钟超时）后 `task.Start()`；
12. 启动 Prometheus metrics 独立端口；
13. `http.Server` 监听（`ReadHeaderTimeout` 防 Slowloris）+ 优雅关闭（Shutdown）。

## 5. 配置体系

[config/config.go](file:///i:/phpstudy_pro/WWW/go/config/config.go) 定义的结构：

| 段 | 关键项 |
|----|--------|
| server | port、mode（debug/release）、read_timeout、max_body_size、trusted_proxies |
| database | dsn 五要素 / max_idle / max_conn |
| redis | addr、db、password |
| jwt | secret、access_ttl（2h）、refresh_ttl（7d） |
| log | filename、level、max_size/max_backups/max_age/compress |
| upload | save_path、max_size（MB）、allow_exts |
| casbin | model_path |
| cors | allow_origins（生产必须白名单）、allow_credentials |
| security | login_fail_closed、token_transport（header/both/cookie）、cookie_secure、cookie_samesite |

关键校验函数：

- **`Validate()`**：端口/超时合法性、`max_body_size > upload.max_size`、`trusted_proxies` 拒绝 `0.0.0.0/0`、`SameSite=none` 必须配 `Secure`；
- **`ValidateSecurity()`**：生产环境 JWT secret < 32 字符即拒绝启动；
- 三态配置（如 `CookieSameSite`）用指针/字符串区分"未配置"与"显式空值"。

## 6. 路由与权限码机制

[router/router.go](file:///i:/phpstudy_pro/WWW/go/router/router.go) 顶部集中定义全部 `permXxx` 权限码常量（与 `sys_menu.permission` 一一对应）。

### 注册函数

```go
protected(system, http.MethodGet, "/user/list", permUserList, userController.FindList)
```

`protected()` 做两件事：

1. 把「方法 + 完整路径」与权限码登记到 `middleware.PermissionTable`（[permission.go](file:///i:/phpstudy_pro/WWW/go/internal/middleware/permission.go)）；
2. 挂到带 `Auth → CSRF → CasbinAuth → OperationLog` 中间件的路由组。

仅需登录态的自助接口（userInfo / changePwd / dashboard / logout）权限码传 `""`。顶层管理类接口用 `protectedAdmin()`（额外要求 admin 角色）。

### 鉴权流程

```
请求 → protected 路由组
  → Auth（JWT 解析 + Redis 吊销检查，fail-closed）
  → CSRF（Cookie 通道时校验 double-submit token）
  → CasbinAuth：c.FullPath() 查权限登记表 → 按当前用户角色逐个 Enforce
  → OperationLog（操作日志，请求体按敏感字段脱敏）
```

- 授权关系来自 `sys_role_menu` + `sys_menu.permission`，启动时及角色变更后经 `SyncPoliciesFromRoleMenus` 自动同步为 Casbin 策略；
- 角色 `admin` 持 `*/*/*/*` 通配；
- **未登记的路由默认拒绝（403）**——漏配不会静默开放，但会导致接口不可用，新增路由后必须实测；
- ⚠️ 不要把权限码做成路由级中间件 `c.Set()`：gin 组中间件先于路由级中间件执行，会导致校验被跳过（历史踩坑）。

### 中间件顺序（全局 → 组）

```
DrainBody → BodyLimit → metrics → Recovery → Logger → Cors → Tenant
  → [protected 组] Auth → CSRF → CasbinAuth → OperationLog
  → [公开接口] RateLimit（login 10/min、refresh 30/min、captcha 30/min、pay-notify 120/min）
  → POST /pay/order 挂 Idempotency；/uploads 挂 UploadSecurity；Swagger 仅非 release 暴露
```

详细说明见 [03-中间件与公共层.md](./03-中间件与公共层.md)。

## 7. 关键依赖关系图

```
cmd/server
  ├── config ──► viper/yaml
  ├── logger ──► zap + lumberjack
  ├── database ─► gorm + mysql
  ├── cache ───► redis
  ├── middleware ─► casbin + 自研适配器 / 权限登记表 / 限频 / 脱敏日志
  ├── router ───► 注册 system/payment/member/captcha 控制器
  │     └── 各 controller ──► service ──► repository ──► gorm
  ├── pkg/auth（JWT） pkg/upload pkg/excel pkg/task pkg/utils
  └── internal/common（响应/错误语义/租户/分页）
```

依赖方向铁律：`pkg/` 不依赖 `internal/`（如 `pkg/task` 的 panic 处理函数由 main.go 注入）；模块间只能经 Service，不能经 Repository。

## 8. 与 AGENTS.md 的少量出入（阅读源码时注意）

- JWT 实际函数名为 `GenerateAccessToken` / `GenerateRefreshToken`（`pkg/auth/jwt.go`），issuer 区分 `go-admin` / `go-admin-refresh`；
- `sys_dept`、`sys_agreement` 已迁移为租户内表（见 `sql/migrations/2026-09-25-*`），不再是全局表；
- `.svg` 不在上传白名单默认值中（`uploads/` 匿名可读 + CSP 头防御 SVG XSS）；
- 实际中间件比 AGENTS.md 描述多出 DrainBody/BodyLimit/metrics/CSRF/RateLimit/Idempotency 等。
